# Design Review Checklist

Each section below is a check the design review makes before a design
history file is released. Each one is a live query block (provenance-ddf
DES-0032) asking for what would fail the check, so an empty section is a
passed check. The same queries are the project's rules in `rules/`, which
`provenance validate` runs at the merge gate (DES-0016): what a rule
reports is exactly what its section here lists.

## Equipment calibration

Verification evidence recorded with equipment whose calibration was due
before the test was run (`rules/equipment-calibration-current.yaml`):

```query
from: VerificationEvidence
where:
  field: equipment_used
  where:
    field: calibration_due_date
    operator: less_than
    value_of: ^execution_date
render: id
```

The same for validation evidence
(`rules/validation-equipment-calibration-current.yaml`):

```query
from: ValidationEvidence
where:
  field: equipment_used
  where:
    field: calibration_due_date
    operator: less_than
    value_of: ^execution_date
render: id
```

## Evidence before its build

Verification evidence executed before the build it names was built
(`rules/evidence-after-build.yaml`):

```query
from: VerificationEvidence
where:
  field: build_tested
  where:
    field: build_date
    operator: greater_than
    value_of: ^execution_date
render: id
```

## Verification coverage

Requirements that no verification protocol verifies yet
(`rules/requirement-verified.yaml`, a warning):

```query
from: Requirement
where:
  field: verified_by
  where:
    field: type
    operator: equals
    value: VerificationProtocol
  aggregation: {type: count}
  operator: less_than
  value: 1
render: id
```

Verification protocols that verify no requirement
(`rules/protocol-verifies-requirement.yaml`):

```query
from: VerificationProtocol
where:
  field: verifies
  aggregation: {type: count}
  operator: less_than
  value: 1
render: id
```

## Risk-benefit analysis

Risks whose residual risk is unacceptable but which have no risk-benefit
analysis (`rules/risk-benefit-required.yaml`):

```query
from: Risk
where:
  - field: residual_acceptability
    operator: equals
    value: unacceptable
  - field: risk_benefit_analysis
    operator: missing
render: id
```

## Change types

Change requests whose change type is outside the approved categories
(`rules/eco-change-type-valid.yaml`):

```query
from: ChangeRequest
where:
  field: change_type
  operator: not_in
  value: [correction, enhancement, safety]
render: id
```

## Deprecated user needs

Requirements implementing a user need that has been deprecated
(`rules/no-implements-deprecated-need.yaml`):

```query
from: Requirement
where:
  field: implements
  where:
    field: status
    operator: equals
    value: deprecated
render: id
```

## Superseded requirements

Requirements that a newer requirement supersedes but that are not yet
deprecated (`rules/superseded-entities-deprecated.yaml`):

```query
from: Requirement
where:
  - field: superseded_by
    operator: exists
  - field: status
    operator: not_equals
    value: deprecated
render: id
```

## Duplicate titles

Requirements sharing a title with another, likely a duplicate or a
copy-paste error (`rules/requirement-title-unique.yaml`, a warning):

```query
from: Requirement
where:
  from: Requirement
  where:
    - field: title
      operator: equals
      value_of: ^title
    - field: id
      operator: not_equals
      value_of: ^id
render: id
```
