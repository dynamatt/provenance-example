# Verification Protocol — Amplitude Control

This document is the verification protocol for amplitude control. The
procedures in it are Verification Protocol entities (`VER-`), and its
devices, equipment and requirements are gathered from them by live query
blocks (provenance-ddf DES-0032), so revising a procedure revises this
document with it. Results are reported in [[DOC-0005]].

## Purpose

To show, by bench test, that the NeuroPulse system adjusts stimulation
amplitude on the evoked response as its requirements state, and that it
never exceeds the 8 mA ceiling under a single fault. The procedures here
are written to be executed as they stand: an execution that passes every
step is objective evidence that the requirements it verifies are met.

## Scope

The requirements this protocol verifies, each through the procedure that
declares it verifies it:

```query
from: Requirement
where:
  field: verified_by
  operator: exists
order_by: order
template: requirement-checklist
```

Requirements no procedure verifies yet are out of scope for this revision,
listed by ID:

```query
from: Requirement
where:
  field: verified_by
  operator: missing
render: id
```

The subsystem allocation [[REQ-0003]] is verified at the system level
through [[REQ-0002]], whose single-fault procedure exercises the ASIC's
current limit; its own inspection of the ASIC design is left to a later
revision of this protocol.

## Device Under Test

Every device an approved procedure in this protocol is run on, each listed
once with the procedures that test it, in [[#devices-under-test]]:

```query
from: Component
where:
  field: test_protocols
  where:
    field: status
    operator: equals
    value: approved
template: device-under-test
```

```caption
kind: table
id: devices-under-test
text: Devices under test.
```

A procedure names the part it tests, not a particular build: the build
each execution was run on is recorded with its result and listed in the
report.

## Test equipment

All procedures run on the bench, with the implant in a saline tank. The
equipment the approved procedures need, each listed once with the
procedures that need it:

```query
from: TestEquipment
where:
  field: needed_by
  where:
    field: status
    operator: equals
    value: approved
template: equipment-summary
```

Each unit used must be within its calibration interval on the day of
execution. The units used, by serial number, are recorded with each
execution, not here, since the same procedure may be run again on
different units.

## Procedures

The approved procedures, in author-assigned order:

```query
from: VerificationProtocol
where:
  field: status
  operator: equals
  value: approved
order_by: id
```

## Acceptance criteria

Each step above carries its own acceptance criteria, and a procedure passes
only when every one of its steps does. A step that does not is a failure of
the procedure: the execution is recorded as `fail`, not repeated until it
passes. The single-fault condition [[VER-0002]] injects is that of
[[REF-0002]].

## Records

Each execution is recorded as Verification Evidence (`EVD-`), naming the
procedure it tests, the commit of this repository holding the procedure as
it was run, the build of the device under test it was run on, its date,
its overall result, a result and pass or fail for each step, and the
equipment used with each item's serial number and calibration due date.
The procedure's versions are its git history, not a number kept by hand.
A procedure revised after it was executed must be executed again. A
procedure is revised through a change request, as [[ECO-0001]] revised
[[VER-0002]].
